# 统一发送设计

日期：2026-11-01  
状态：待审阅

## 目标

调用方用同一个发送入口，把一条消息同步送到一条已配置的通道。对内和对外的差别只在地址本身：邮箱、手机号、用户 ID、企业微信 ID，或机器人通道自己的地址。

## 已确认决策

| 项 | 选择 |
|----|------|
| 谁选通道 | 调用方指定一条通道 |
| 地址从哪来 | 调用方传入最终地址，或传入群组 ID。发送层不查组织目录 |
| 通道是什么 | 一条已配置的管道。密钥和机器人地址在通道配置里 |
| 消息体 | 标题、正文、可选链接。各适配器自己渲染 |
| 结果 | 同步返回。每个地址一行回执。调用方自己重试 |
| 入口形状 | 一个 `send`。地址是字符串。空地址表示发给通道自己 |

## 不包含

- 把用户、部门、外部联系人解析成地址
- 一次调用发送到多条通道
- 排队、自动重试、幂等键、发送记录的保存和查询
- 模板，以及按通道另写一套文案
- 通道和群组的管理界面。本设计只规定发送时要读到的字段

调用方自行控制一次调用的地址数量。发送层不设上限，也不拆分名单。再次调用会再次投递，发送层不合并重复请求。

## 发送契约

```text
send(通道 ID, 地址列表 或 群组 ID, 消息) → 整单拒绝 或 回执列表

消息 = 标题 + 正文 + 可选链接
回执 = 地址 + 是否送达 + 可选失败原因
```

一次调用只使用一条通道。地址列表和群组 ID 只能出现一个。

「传入地址列表」包括传入空数组。「未传」表示调用方没有给这个参数。只含空白的群组 ID 视为未传。只含空白的链接视为未传。

需要收件人的通道是：邮件、短信、站内信、企业微信应用。

- 未传地址列表，也未传群组 ID：整单拒绝，原因「缺少收件人」
- 传入空数组，且未传群组 ID：整单拒绝，原因「缺少收件人」
- 传入地址列表（含空数组）又传入群组 ID：整单拒绝，原因「地址列表和群组不能同时传入」

三种机器人是：钉钉机器人、企业微信机器人、IYUU。

- 未传地址列表，也未传群组 ID：合法。回执一行，地址一栏是通道 ID
- 传入了地址列表或群组 ID：整单拒绝，原因「机器人不能带收件人」

群组里的地址与直接传入的地址使用同一套规则。重复地址按出现次数各投递一次，各占一行回执。回执顺序与地址顺序一致。地址先去掉首尾空白，回执里写去掉空白后的值。

标题或正文去掉空白后为空，整单拒绝。链接可以不传。

## 通道

发送层读到的通道字段：

| 字段 | 含义 |
|------|------|
| 通道 ID | 调用方传入的标识 |
| 类型 | 下表七种之一 |
| 启用 | 停用则整单拒绝 |
| 配置 | 该类型的密钥和协议参数，不含收件人 |

| 类型 | 配置 |
|------|------|
| 邮件 | SMTP 主机、端口、账号、密码、发件人 |
| 短信 | 供应商访问密钥、签名、接口地址 |
| 站内信 | 无 |
| 企业微信应用 | 企业 ID、应用 ID、应用密钥 |
| 钉钉机器人 | Webhook 地址、加签密钥 |
| 企业微信机器人 | Webhook 地址 |
| IYUU | 令牌 |

## 群组

群组是一份已经解析好的地址名单。字段：

| 字段 | 含义 |
|------|------|
| 群组 ID | 调用方传入的标识 |
| 通道类型 | 邮件、短信、站内信、企业微信应用之一 |
| 地址列表 | 该类型的最终地址。发送时若列表为空，整单拒绝 |

群组不绑定某一条通道。任意一条相同类型且已启用的通道都可以发送这个群组。机器人没有群组。

读取顺序：先确认群组存在，再确认类型与当前通道一致，再确认地址列表非空。因此一个空的、类型也不符的群组，原因是「群组类型与通道不符」。

## 发送步骤

按这个顺序检查，命中第一条就整单拒绝，不继续后面的检查，也不返回回执：

1. 通道不存在 → 「通道不存在」。通道已停用 → 「通道已停用」。
2. 标题或正文去掉空白后为空 → 「标题或正文为空」。
3. 解析收件人。
   - 地址列表和群组 ID 同时传入 → 「地址列表和群组不能同时传入」。
   - 机器人收到地址列表或群组 ID → 「机器人不能带收件人」。
   - 需要收件人的通道未传群组 ID，且未传地址列表或传入空数组 → 「缺少收件人」。
   - 群组不存在 → 「群组不存在」。
   - 群组类型与通道类型不一致 → 「群组类型与通道不符」。
   - 群组地址列表为空 → 「群组为空」。
4. 把通道配置、地址列表和消息交给该类型的适配器。
5. 按地址顺序返回回执。投递开始之后，不再改成整单拒绝。

从群组发送时，第 4 步使用群组中的地址顺序。

## 适配器与报文

每种类型一个适配器。适配器接收通道配置、地址列表和消息。它不读取群组。需要收件人的四种通道，回执每个地址一行。适配器可以用供应商的批量接口，但不得把多个收件人合成一次投递后只返回一行。某一批整体失败时，这一批里的每一行使用同一个失败原因。

格式不合法的地址不发给供应商，该行失败，原因固定为「地址格式不正确」。其余地址继续投递。

供应商拒绝、网络失败或超时，只让对应行失败，原因使用供应商或网络返回的说明。第一条尚未发出就无法连接时，每一行失败且原因相同。已经送达的行保持送达。

| 类型 | 合法地址 | 报文 |
|------|----------|------|
| 邮件 | 去掉空白后匹配「非空且不含空白和 `@` 的局部 + 一个 `@` + 非空且不含空白和 `@` 的域名」 | 主题是标题。正文是纯文本。有链接时，正文后加一个换行再写链接 |
| 短信 | 去掉空白后是可选的一个 `+`，后面全是数字，至少一位 | 只发送正文。有链接时，正文后加一个换行再写链接。标题不进入短信 |
| 站内信 | 去掉空白后非空。不核对该用户是否存在 | 保存标题、正文和链接。未传链接则链接为空 |
| 企业微信应用 | 去掉空白后非空 | 文本为标题、空行、正文。有链接时再加一个空行和链接 |
| 钉钉机器人 | 无地址。回执地址一栏是通道 ID | Markdown。标题用消息标题，正文用消息正文。有链接时正文后加一个换行再写链接。使用配置中的地址和加签密钥 |
| 企业微信机器人 | 同上 | Markdown，结构与钉钉机器人相同。使用配置中的 Webhook 地址 |
| IYUU | 同上 | 通知标题用消息标题，通知内容用消息正文。有链接时内容后加一个换行再写链接。使用配置中的令牌 |

站内信写入成功即该行送达。写入失败则该行失败，原因来自写入过程。

## 失败一览

整单拒绝的原因只有下面这些，且没有回执：

- 通道不存在
- 通道已停用
- 标题或正文为空
- 地址列表和群组不能同时传入
- 缺少收件人
- 机器人不能带收件人
- 群组不存在
- 群组类型与通道不符
- 群组为空

回执中的失败只有两类：原因恰好是「地址格式不正确」，或原因是供应商、网络、写入过程返回的说明。一部分行失败时，这次调用仍然返回回执，不算整单拒绝。

## 测试

发送入口使用假的通道、群组和适配器，不访问外部服务。

整单拒绝各至少一条：通道不存在、通道已停用、标题为空、正文为空、空白标题、地址列表和群组 ID 同时传入、需要收件人的通道两者都未传、需要收件人的通道传入空数组、机器人传入地址、机器人传入群组 ID、群组不存在、群组类型不符、群组为空。检查顺序：通道已停用优先于消息和收件人问题；群组类型不符优先于群组为空。

成功路径：

- 传入群组 ID 时，适配器收到的地址顺序与群组一致，回执顺序一致。
- 同一列表中一条地址格式不合法时，该行原因是「地址格式不正确」且未发给供应商，其余地址照常投递。
- 适配器让其中一行失败时，调用返回回执，只有该行失败。
- 重复地址产生多行回执。
- 机器人未传地址和群组时，回执一行，地址是通道 ID。
- 只含空白的群组 ID 视为未传。只含空白的链接不出现在报文中。

每种适配器使用假供应商，确认：报文符合上表；非法地址不调用供应商；供应商让其中一个地址失败时另一行仍可送达；连接在第一条发出之前失败时每一行原因相同。三种机器人各确认回执中的地址是通道 ID。
