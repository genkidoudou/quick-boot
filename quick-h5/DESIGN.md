# QuickBoot H5 视觉与信息架构设计

改动用户看得见的界面前先读本文。本文约定 **quick-h5**（uni-app x + RiceUI + vapor / 蒸汽模式，含 H5、小程序、App）的产品定位、三栏信息架构、Soft Glass 视觉与页面原型。管理端 **quick-ui** 的桌面设计见 `quick-ui/DESIGN.md`；两端气质对齐，但 **壳层与交互按移动端重做**，禁止把 PC 侧栏表格原样塞进手机。

静态对照预览（实现前 / 回归）：

- `design-previews/tab-schemes-5.html` → **方案 A Soft Glass 产品壳**（已选定）
- `design-previews/tab-ia.html` → 三栏信息架构说明

组件栈：**仅 `rice-*`** + Soft Glass 氛围层；颜色优先 `--rice-*` / 主题变量，主色目标 **`#8D51F9`**。禁止混用 uview / TMUI 等其它全家桶。

---

## 1. 产品定位（方案 A）

| 项 | 约定 |
|----|------|
| 产品类型 | B 端 **中台移动壳**：管理员出门也能「看一眼、进模块、处理消息」 |
| 视觉方向 | **Soft Glass**：消费级产品壳 + 安静运维面（对标 MoviePilot v3 / Apple 向玻璃感，而非传统灰底后台） |
| 与 quick-ui | 共用品牌主色、玻璃/卡片语言与业务能力映射；**不**共用侧栏、顶栏、C7 表格壳 |
| 非目标 | 不是消息优先社交 App、不是 SRE 终端、不是纯指标看板、不是极简纸感笔记 |

成功标准：用户打开 App 能在 3 秒内理解「今天有什么要处理」；从工作台 2 次点击内进入常用模块；我的页完成主题与退出，不夹带管理表格。

## 2. 信息架构：三栏

底部原生 `tabBar`（RiceUI 无独立 tabbar）。登录页 **不在** tabBar 内。

| Tab | 路由（约定） | 职责 | 放什么 | 不放什么 |
|-----|--------------|------|--------|----------|
| **首页** | `pages/index/index` | 态势与待办 | Soft Glass 欢迎横幅、「今日关注」摘要卡、最近消息/告警轻列表 | 完整系统管理表、密宫格 |
| **工作台** | `pages/workbench/workbench` | 能力启动器 | 按域分组的入口宫格（消息 / 运维 / 系统 / 报表），权限裁剪 | 账号设置、退出登录 |
| **我的** | `pages/mine/mine` | 账号与偏好 | 头像区、资料/改密、我的消息、外观主题、关于、退出 | 用户/角色/字典等管理入口 |

### 2.1 首页（态势）

结构自上而下，**一个首屏一个主叙事**：

1. **媒体欢迎面**（`.qb-media-surface` 气质）：短眉题（如「今天 · 产品工作台」）+ 问候 + 一句产品向副文，避免说明书口吻。
2. **今日关注**：2～4 张摘要卡（站内信未读、任务失败、登录异常等）。卡片用品牌染色 / 彩色摘要原型，**不是**数据大盘 KPI 墙。
3. **最近动态**（可选）：站内信或系统通知 2～5 行，点进详情/列表。

### 2.2 工作台（办事）

- 短横幅说明「按模块进入」即可，勿再放大仪表盘。
- 入口按域分段标题 + **4 列宫格**（小屏可 4，极窄可 3）：
  - **消息**：站内信、渠道、群组、发送记录…
  - **运维**：定时任务、任务日志、登录日志、操作日志、监控…
  - **系统**：文件、用户、角色、部门、字典、参数、OAuth…
  - **报表**：报表设计、BI（外链 / WebView 承接 Jimu，与 quick-ui 一致）
- 低频能力可收进「更多」。无权限入口不展示（勿灰置一堆不可点）。
- 点入口进入 **二级列表/详情页**（搜 → 列表 → 详情/表单），交互对齐移动端，不要求像素级复刻 C7 桌面表。

### 2.3 我的（账号）

- 顶部身份卡（头像字标 / 昵称 / 角色摘要）。
- 分组列表：资料与安全 → 消息与通知 → 外观（Soft Glass / 深浅色）→ 关于。
- **退出登录**单独一组，破坏性操作视觉明确（error / 警示色文字），退出后 `reLaunch` 登录页。

### 2.4 登录（壳外）

- 启动页；自定义导航；品牌名是第一视觉；氛围光斑 + 大圆角登录卡。
- 账号 + 手机双 Tab；验证码多端策略见既有登录 spec。
- 登录成功进入 **首页 Tab**（`reLaunch` / 等价），不是工作台。

## 3. Soft Glass 视觉（H5）

### 3.1 原则

- **品牌优先**：登录与首页横幅承载品牌温度；列表与表单保持安静。
- **一层玻璃**：模糊/半透只做在页面氛围、底栏玻璃感（若自定义）与主卡片外框；卡片内部用静态浅底，不叠多层 `backdrop-filter`。
- **主色克制**：`#8D51F9` 用于主按钮、Tab 选中、关键链接与焦点；大面积画布用中性背景。
- **端一致**：H5 / 小程序 / App 同一套间距与圆角语义；蒸汽模式禁用不支持的 CSS。

### 3.2 令牌映射（移动端）

业务页优先消费 **Rice 主题变量**；Soft Glass 语义与 quick-ui `--qb-*` 对齐时，用有限 CSS 变量或 `styles/soft-glass.css` 覆盖，**不**引入第二套 UI 字体栈抢 Rice。

| 语义 | 建议落点（H5） | 用途 |
|------|----------------|------|
| 画布 `background` | `--rice-background` / `#F2F2F7` 气质 | 页面底 |
| 卡片 `card` | `--rice-background-2` 或半透白 | 登录卡、摘要卡、分组列表 |
| 正文 / 次文 | `--rice-text-color` / `--rice-text-color-2` | 标题与说明 |
| 主色 `primary` | `--rice-primary-color` → `#8D51F9` | 按钮、Tab 选中 |
| 成功 / 警告 / 危险 | Rice 语义色 | 徽章与退出 |
| 圆角 | 入口面约 `20px`（lg）；控件随 Rice | 横幅、登录卡、摘要卡 |
| 底栏避让 | 为 `tabBar` + 安全区留白 | 列表最后一项不被挡住 |

深色：走 Rice `setTheme('dark')`；横幅可用深色渐变媒体面，正文保持可读，禁止灰字压灰底。

### 3.3 字体与数字

- 跟随 Rice / 系统字体即可；**不**为 H5 再引入 Inter/Outfit 等与管理端抢戏的第二展示字体，除非全端统一改造。
- 字重：正文 400、标签 500、标题 600。
- 未读数、任务数等用等宽数字感（可行时 `tabular-nums`），避免刷新跳动。

### 3.4 动效

- 页面进入：轻微、短、可关；不做每张卡轮流 fade-up。
- 交互反馈：按钮 loading、Tab 切换、下拉刷新（若有）即可。
- 登录氛围光斑可保留，但须克制，暗黑下不刺眼。

## 4. 表面原型（H5 精简）

相对 quick-ui「七类表面」，移动端收成 **六类**，新增页必须对号入座：

1. **媒体欢迎面** — 登录品牌区、首页横幅：渐变/氛围底 + 亮色字（on-media），大圆角。
2. **摘要关注卡** — 首页「今日关注」：浅玻璃/浅底卡片 + 短标题 + 一句说明 + 可选软徽章。
3. **动态列表行** — 消息/通知行：左识别色块或字标、中标题 + 一行摘要、右时间/未读点（首页「最近动态」可用）。
4. **启动器宫格** — 工作台：色块图标 + 短标签；一屏可扫完，勿无限长墙（多域用分段）。
5. **分组设置列表** — 我的：整组圆角容器 + 行内左右说明/控件。
6. **二级业务页** — 列表/详情/表单：安静运维面；顶栏返回 + 搜索 + 筛选 + 列表；状态用语义徽章。业务列表行统一用下方 **「标题 + 两行摘要」** 规范。

弹出层：统一 Rice Dialog / ActionSheet 注册页；蒙层与圆角跟 Rice，不自造第二套 modal。

## 5. 二级列表与详情（强制样式）

对照预览：`design-previews/tab-schemes-5.html` 方案 A → 工作台 → **用户管理** / **站内信**。  
从工作台入口进入的管理类列表（用户、角色、任务、文件、消息等）**默认采用同一套行样式**，禁止只显示「标题 + 一行挤在一起的杂讯」。

### 5.1 列表页骨架

```
[‹ 返回]  页面标题          [次要操作，如新增]
搜索框（占位说明可搜字段）
筛选 chip（全部 / 状态 / 范围…，可横滑）
圆角玻璃列表容器
  └─ 列表行 × N
```

- 二级页 **隐藏 tabBar**；底栏避让改为普通安全区即可。
- 返回回到工作台（或来源 Tab）；详情返回列表。

### 5.2 列表行：「标题 + 两行摘要」（默认）

左对齐主信息，右侧仅放 **状态徽标**（或时间，二选一优先状态；消息类可用时间）。

| 区位 | 内容 | 样式要点 |
|------|------|----------|
| 左 | 字标 / 头像色块（约 42×42、圆角约 14） | Soft Glass 渐变或语义色，单字/双字 |
| 中 · 标题 | 主识别名 | 14px、字重 600；用户例：`userName · 昵称` |
| 中 · 第 1 行 | 组织/分类维 | 12px、次文色；用户例：`部门 · 角色：xxx` |
| 中 · 第 2 行 | 联系/活跃维 | 12px、更弱文色；用户例：`手机 · 邮箱` 或 `手机 · 最近登录` |
| 右 | 状态 | 软底胶囊：`正常` / `停用` 等；勿大色块 |

规则：

- **必须**有标题 + **两行**摘要；单行摘要视为不合格。
- 两行过长用省略号，不折成三行以上。
- 字段映射按业务换皮，结构不变。示例：

| 模块 | 标题 | 第 1 行 | 第 2 行 | 右 |
|------|------|---------|---------|----|
| 用户 | `userName · 昵称` | 部门 · 角色 | 手机 · 邮箱/最近登录 | 正常/停用 |
| 站内信 | 消息标题 | 发送方/类型摘要 | 正文摘录 | 时间（未读可用点） |
| 定时任务 | 任务名 | Cron/分组 | 上次结果或下次触发 | 运行状态 |
| 文件 | 文件名 | 分类/大小 | 上传人 · 时间 | 可选类型标 |

### 5.3 详情页

- 顶栏：返回列表 + 标题 + 编辑等次要操作。
- 身份区（可选）+ 玻璃卡片内 **标签行 + KV 字段表**（标签宽约 88px，值用正文色）。
- 底区操作：返回 / 业务次要操作 / 主操作（primary），2～3 列均可。

### 5.4 验收（列表）

- [ ] 业务列表行均为「标题 + 两行摘要 + 右侧状态/时间」
- [ ] 有搜索与至少一组筛选 chip（可先静态）
- [ ] 二级页无 tabBar；可返回工作台
- [ ] 对照 `tab-schemes-5.html` 用户列表密度与层级

## 6. 组件与工程约束

- 写任何 `rice-*` 前查 `.cursor/skills/rice-ui/references/api/`；写后跑  
  `node .cursor/skills/rice-ui/scripts/verify-rice-usage.mjs <路径>` → **0 违规**。
- 脚本 `lang="uts"`；条件编译区分 WEB / 非 WEB（如 API_BASE、Captcha）。
- 鉴权：Bearer `accessToken`；请求加签与后端 `qc.sign` 对齐（见 `api/sign.uts`）。
- Tab 页与需登录的二级页：无 token → `reLaunch` 登录页。
- 图标：`tabBar` 使用 `static/tab/*`；业务入口图标可用色块字标首期，后续再换统一图标集。

## 7. 与方案 B–F 的边界（防漂移）

实现与评审时若出现以下倾向，视为偏离方案 A，需先改 DESIGN 再改代码：

| 倾向 | 更像 | 处理 |
|------|------|------|
| 首页改成会话流、Tab 文案改「消息」 | 方案 B | 拒绝或单独立项 |
| 首页改成 P1/P2 终端告警墙 | 方案 C | 拒绝或单独立项 |
| 首页只剩大磁贴应用市场 | 方案 D | 工作台可吸收部分，首页仍保留态势 |
| 去掉玻璃与摘要卡、改纸感清单 | 方案 E | 拒绝 |
| 首页改 KPI 大盘 | 方案 F | 拒绝；指标最多作为关注卡上的小数 |
| 业务列表只有标题或标题+单行塞满 | — | 拒绝；必须「标题 + 两行摘要」 |
